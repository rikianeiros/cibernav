Antes de escribir una línea de código
⚡ Verificaciones obligatorias
  • Verificar driver Alfa AWUS036ACH en modo monitor
    sudo airmon-ng start wlan0  →  sin errores
  • Montar laboratorio en casa: router secundario + 3-4 dispositivos de prueba
    Sin lab propio = sólo puedes probar en el barco. Eso frena el desarrollo.
  • Instalar el stack base en Kali y verificar imports
    pip install python-nmap scapy reportlab openpyxl mac-vendor-lookup
  • Confirmar si los buques objetivo tienen NMEA sobre IP
    Pregunta al responsable de sistemas antes de construir el módulo NMEA
  • Definir la estructura de carpetas del proyecto y crear el repositorio git
    Ver estructura abajo en Fase 1
Alertas del premortem a tener en cuenta
⚠ Scope creep: Si en cualquier momento piensas "podría añadir también...", lo apuntas en un archivo v2-ideas.md y no lo tocas hasta que v1 genere su primer PDF real.
🛑 Stack demasiado grande de golpe: El orden de las fases no es opcional. Cada fase tiene un entregable concreto. Si saltás a la fase 3 sin tener el PDF de la fase 1, vas a estar depurando dos capas desconocidas a la vez.
ℹ El informe es el producto: Dedica el mismo tiempo al lenguaje del informe que al código que lo genera. Define las frases exactas para cada hallazgo antes de codificar el generador.
Fases de desarrollo
1
Parser + Generador de PDF
El núcleo. Sin esto, nada más tiene sentido.
2 semanas ⌄
Objetivo: Dado un XML de salida de Nmap, generar un PDF de auditoría completo en lenguaje llano. Sin escáner en vivo todavía — trabajas con archivos XML estáticos que tú mismo generas a mano en tu lab. Al final de esta fase tienes algo que funciona y que puedes mostrar.
naval-audit/
  modules/
    parser.py  # lee el XML de nmap
    classifier.py  # decide rojo/amarillo/verde
    plain_language.py  # TODAS las frases del informe
  report/
    pdf_gen.py
    excel_gen.py
  data/
    mac_vendors.json
    risky_ports.json  # 23,21,80,8080...
  samples/
    scan_lab.xml  # XMLs de prueba
  main.py
  v2-ideas.md  # ideas futuras, no tocar
Librerías
python-nmap reportlab openpyxl mac-vendor-lookup xml.etree
Tareas clave
  • Parser de XML nmap → diccionario Python
  • Clasificador de puertos de riesgo
  • Lookup MAC → fabricante
  • plain_language.py: frases para cada hallazgo
  • Layout PDF: portada, semáforo, tablas
plain_language.py — esto es crítico
  • Antes de codificar el PDF, escribe en este archivo una frase para cada hallazgo posible. Ejemplo: puerto 23 abierto → "Este dispositivo tiene activo un protocolo antiguo (Telnet) que transmite contraseñas sin cifrar. Recomendación: desactivarlo."
  • Dale el draft a alguien no técnico a leer. Si no lo entiende, reescribe. El código viene después.
Entregable: python main.py --input samples/scan_lab.xml --output informe.pdf genera un PDF real con portada, semáforo y tabla de dispositivos.
2
Escáner en vivo
Integrar Nmap real. El PDF ahora viene de una red real.
1 semana ⌄
Objetivo: Sustituir el XML estático por un escaneo real de python-nmap. Conectado a tu lab, ejecutas el script y en 2 minutos tienes el PDF con los datos reales de esa red.
Añadir a módulos
  • Nuevo scanner.py: wrapper de nmap
  • Detección de OS con -O
  • Detección de versiones -sV
  • Rango de IPs configurable
  • Timeout y manejo de errores
Tipos de escaneo
  • ARP scan — descubrimiento rápido de host
  • SYN scan — puertos sin completar handshake
  • UDP scan — servicios como SNMP, DNS
  • Script scan --script vuln
Ojo: Prueba siempre primero en tu red de casa. Nunca lleves código sin testear a un entorno naval.
Entregable: python main.py --scan 192.168.1.0/24 escanea la red y genera el PDF directamente.
3
WiFi pasivo — probe requests y beacons
Modo monitor. Redes previas de móviles. Inventario de APs.
2 semanas ⌄
Prerequisito BLOQUEANTE: El driver de la Alfa debe funcionar en modo monitor. Si no pasó la verificación pre-fase, esta fase no empieza. No hay workaround.
Módulo wifi_passive.py
  • Activar modo monitor: wlan0mon
  • Capturar beacons → inventario de APs
  • Capturar probe requests → SSIDs previos
  • Captura por tiempo configurable (ej. 3 min)
  • Desactivar monitor al terminar
Qué se extrae
  • SSID + BSSID + canal + cifrado de cada AP
  • WPS habilitado: sí/no
  • Por cada dispositivo visto: MACs + redes que busca
  • Fabricante del dispositivo (MAC lookup)
  • Señal de alerta si SSID contiene nombre de base
En el informe PDF — sección de perfiles
  • Tabla: dispositivo · fabricante · redes buscadas
  • Alerta si algún SSID buscado parece red corporativa o base
  • Resumen: "Se detectaron X dispositivos buscando Y redes distintas"
Entregable: python main.py --passive --duration 180 captura en modo monitor 3 minutos y añade la sección de perfiles WiFi al informe.
4
Módulo NMEA / Navegación
Condicional: sólo si los sistemas están en red IP.
1.5 semanas ⌄
Prerequisito: Confirmación de que existe un multiplexor NMEA con salida TCP en el buque objetivo. Si no hay IP en NMEA, esta fase no aplica y se puede saltar directamente a la 5.
Módulo nmea.py
  • Escaneo de puerto TCP 10110 en la subred
  • Conexión y lectura de sentencias NMEA
  • Parser: GGA, RMC, VHW, DPT, MWV
  • Detección de dispositivos AIS en red
  • Check de autenticación: ¿requiere credenciales?
En el informe — sección navegación
  • Listado de dispositivos NMEA accesibles
  • ¿Tienen autenticación? sí/no → rojo si no
  • Interfaces web encontradas (Garmin, Furuno...)
  • Credenciales por defecto detectadas → CRÍTICO
  • Firmware desactualizado si versión visible
Importante: Este módulo es sólo lectura. No modificar configuración ni inyectar datos, aunque sea técnicamente posible. Los hallazgos van al informe, no se actúa sobre ellos.
Entregable: Sección "Sistemas de Navegación" en el PDF con hallazgos de AIS, plotters y multiplexores accesibles.
5
Polish — Integración CVE y calidad
Cuando todo funciona, se mejora.
1.5 semanas ⌄
Objetivo: Con v1 funcionando y probado en real, mejorar la calidad del output. Añadir consultas a CVE/NIST para enriquecer los hallazgos con datos oficiales. Afinar el lenguaje del informe basado en feedback real.
Integración CVE/NIST
  • API pública de NVD: services.nvd.nist.gov
  • Buscar por CPE el software/versión detectado
  • Añadir CVSSv3 score al hallazgo
  • Cachear resultados localmente
Mejoras de informe
  • Historial: comparar con escaneo anterior
  • "Novedades desde el último informe"
  • Portada configurable: nombre buque, fecha, operador
  • Modo resumen ejecutivo (1 página)
Entregable: Herramienta completa, probada en lab y en entorno real naval, con informe que un mando no técnico puede leer y entender en menos de 5 minutos.
